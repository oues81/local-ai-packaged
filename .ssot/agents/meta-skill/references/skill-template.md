# Reference: Generated Skill Structure

<overview>
This reference defines the structure of the migration skill generated by `acos-migration-generator`. Use it as a checklist when generating the skill.
</overview>

## Required files

The generated skill must contain at least:

```text
.ssot/skills/acos-migrate-<project>/
├── SKILL.md                              # Router + intake
├── workflows/
│   └── migrate.md                        # Main migration playbook
└── references/
    ├── legacy-mappings.md               # Legacy → ACOS mapping tables
    ├── decision-gates.md                # 4 human approval gates
    └── acos-cli-guide.md                # CLI outputs and failures
```

## Recommended files

If the project has specific needs, also generate:

```text
references/
├── acp-registry.md                       # If .acp/registry.json exists
├── hook-merge.md                         # If native hooks need manual merging
├── fabric-rules.md                       # If Fabric ecosystem
└── project-specific-notes.md           # Any other project-specific guidance
```

## SKILL.md structure

The generated `SKILL.md` should follow this outline:

```markdown
---
name: acos-migrate-<project>
description: Migrate <project> to ACOS v0.4.0+ with project-specific mappings.
---

<objective>
What this skill does and what it preserves.
</objective>

<quick_start>
1. Step 1
2. Step 2
3. Step 3
</quick_start>

<essential_principles>
<principle name="...">...</principle>
</essential_principles>

<intake>
Ask the user what they want.
</intake>

<routing>
Table mapping responses to workflows.
</routing>

<reference_index>
List of references.
</reference_index>

<workflows_index>
List of workflows.
</workflows_index>

<success_criteria>
When is this skill considered complete.
</success_criteria>
```

## Workflows/migrate.md structure

The generated playbook should follow this outline:

1. **Phase 0 — Pre-flight checks**
   - Verify project root.
   - Check git status.
   - Create `acos-migration` branch.

2. **Phase 1 — Backup and audit**
   - Create off-Git backup ZIP.
   - Create rollback branch.
   - Rename `.ssot` to `.ssot.legacy`.
   - Run `pre-init-audit --migration-plan`.
   - Decision Gate 1.

3. **Phase 2 — Initialize canonical structure**
   - Run `npx acos init --adopt`.
   - Verify generated structure.

4. **Phase 3 — Apply project-specific mappings**
   - Move/merge rules.
   - Move/merge agents.
   - Move/merge workflows as entrypoints.
   - Handle ACP registry.
   - Handle hooks.
   - Migrate context files.
   - Add protected paths.
   - Decision Gate 2.

5. **Phase 4 — Remove legacy projections**
   - Delete legacy client-side files that will be regenerated.

6. **Phase 5 — Generate projections**
   - Run `npx acos --fix`.

7. **Phase 6 — Validate**
   - Run `npx acos --validate`, `npx acos --check`, `npx acos-doctor`.
   - Verify critical files.
   - Decision Gate 3.

8. **Phase 7 — Cleanup and commit**
   - Review diff.
   - Delete `.ssot.legacy/` and reports.
   - Update status files.
   - Decision Gate 4.

## References structure

### legacy-mappings.md

- Core rule: when in doubt, preserve.
- Rules table.
- Workflows / entrypoints table.
- Workflow duplicates resolution framework.
- Agents table.
- Agent collision framework.
- Scripts and ACP table.
- Configuration and indexing table.
- Editor and non-ACOS tooling table.
- Directories to archive.

### decision-gates.md

- Gate 1: audit plan approval.
- Gate 2: merge and registry approval.
- Gate 3: validation approval.
- Gate 4: final commit approval.
- Default answer: STOP.
- Escalation conditions.

### acos-cli-guide.md

- Pre-migration audit.
- Initialize and adopt.
- Generate projections.
- Validate structure.
- Check drift.
- Doctor.
- Post-migration transition.
- Repair workflow.
- Project-specific expected outputs.

## Quality checklist

Before finishing generation, verify:

- [ ] All reference files referenced by workflows exist.
- [ ] All `workflows.json` `category` values are allowed.
- [ ] All entrypoint `description` fields match frontmatter.
- [ ] All protected paths are marked `managed: false` where appropriate.
- [ ] All four decision gates have exact questions.
- [ ] The playbook does not mutate files before Gate 1.
- [ ] The playbook does not run `--fix` before Gate 2.
- [ ] The playbook does not cleanup before Gate 3.
- [ ] The playbook does not commit before Gate 4.
