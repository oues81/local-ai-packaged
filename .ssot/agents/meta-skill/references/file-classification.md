# Reference: Legacy File Classification

<overview>
This reference helps classify legacy files found during project analysis. For each file, determine whether it should be moved, merged, preserved, or archived.
</overview>

## Classification actions

| Action | Meaning |
|---|---|
| `move` | Copy the file to the canonical ACOS location with minimal changes. |
| `merge` | Combine the legacy content with the ACOS canonical file. |
| `preserve` | Keep the file where it is; mark as protected if ACOS might overwrite it. |
| `archive` | Move to `.ssot.legacy/archived/` or delete after user approval. |
| `review` | Requires a human decision before action. |

## Directory classification guide

| Subdirectory | Typical action | Notes |

## How to decide when unsure

1. **Is it a projection?** If the file is in a directory that ACOS targets (e.g., `.cursor/commands/`, `.kilo/skills/`), it will be regenerated. Delete the legacy version after migration.
2. **Is it canonical source?** If the file is the original source of truth (e.g., `.ssot/rules/`), move it to `.ssot/agents/rules/`.
3. **Is it non-ACOS tooling?** Preserve it and add to `.ssot/protected-paths.json`.
4. **Is it obsolete?** Archive it.
