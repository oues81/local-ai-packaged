GSD Core is an optional execution engine beneath ACOS, not a second source of truth.
ACOS keeps canonical project constitution, architecture, decisions, specifications, status,
and handoff in `.ssot/`; adapter-owned working state stays in ACOS-owned paths and is mapped
back to the canonical files without overwriting newer canonical facts.

Prerequisites: Node.js 22+ and npm 10+. Verify the runtime before running this workflow. If
either requirement is missing, stop and report the gap; this workflow refuses unsupported
runtimes.

Phase A is read-only. Do not install or mutate anything until the user explicitly authorizes
Phase B.

1. Confirm the runtime with `node --version` and `npm --version`. If either is below Node.js 22
   or npm 10, refuse the rest of this workflow and report the required versions.
2. Run the read-only plan to see every local and user-level path the upstream GSD installer
   would touch:
   `npx --no-install acos-gsd --operation plan --profile .ssot/gsd-profile.json --output text`
3. Review the plan. It must describe only ACOS-owned paths, including `.acos/gsd-core/`, and
   must not suggest global or user-level mutations outside ACOS control.
4. Run the verify command to check the adapter declaration, pinned version, checksum, and
   enabled client surfaces:
   `npx --no-install acos-gsd --operation verify --profile .ssot/gsd-profile.json --output text`
5. Treat raw `gsd-*` commands as internal upstream mechanics; they are not the ACOS public
   interface and must not be exposed as numbered entrypoints.
6. If the user asks to proceed, stop after Phase A and request explicit authority for Phase B
   installation. Actual installation must write only to ACOS-owned paths (`.acos/gsd-core/`),
   preserve unrelated client files, and leave `.ssot/` as canonical.
7. Phase B — authorized install only. Run the isolated install with the explicit `--authorized`
   flag. The command refuses to run without it, redirects the installer into a temporary scratch
   directory, verifies that no write escaped into the real `$HOME`/`$USERPROFILE`, copies only the
   intended GSD runtime assets into `.acos/gsd-core/`, and records an ownership manifest:
   `npx --no-install acos-gsd --operation install --profile .ssot/gsd-profile.json --output text --authorized`
8. After installation, confirm the manifest exists at `.acos/gsd-core/manifest.json` and lists
   every copied asset with its SHA-256 hash. Verify that the capability map in
   `.ssot/gsd-profile.json` still maps each ACOS delivery lifecycle ID (`delivery.spec`,
   `delivery.plan`, `delivery.execute`, `delivery.verify`, `delivery.ship`) to the pinned GSD
   Core capabilities.
9. Phase B — authorized uninstall only. To remove the isolated install, run the uninstall command
   with `--authorized`. It removes exactly the paths recorded in the manifest and refuses if the
   manifest is missing or corrupt:
   `npx --no-install acos-gsd --operation uninstall --profile .ssot/gsd-profile.json --output text --authorized`

After setup, the standard numbered lifecycle (`0100-spec`, `0140-plan`, `0260-execute`,
`0300-verify`, `0440-ship`) will delegate to GSD Core when configured, while the ACOS
entrypoints remain the public invocation surface.
