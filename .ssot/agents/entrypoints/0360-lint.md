Run the project's linter and fix auto-fixable issues for the active feature.

1. Determine the feature ID from the user's request or the active spec.
2. Detect the linter by inspecting config files: `eslint.config.*`, `.eslintrc*`, `biome.json`, `.prettierrc*`, `ruff.toml`, `pyproject.toml [tool.ruff]`, `mypy.ini`, `.golangci.yml`, `clippy.toml`. If no linter is detected, skip with a note (FM-001).
3. Run the linter over the files changed by this feature (use `git diff --name-only` to scope).
4. Apply auto-fixes if the linter supports them (`--fix`, `--write`, `format`).
5. Re-run the linter to confirm remaining issues are non-auto-fixable.
6. Produce `specs/<feature-id>/lint-report.md` with:
   - Linter detected and command used.
   - Issues before fix, issues auto-fixed, issues remaining.
   - Files modified by auto-fix.
7. Do not commit — the user or `delivery.ship` handles commits. Remaining issues feed `delivery.converge` as quality findings.
