Generate or update project documentation, verified against the actual codebase.

1. Determine the documentation scope from the user's request (README, API docs, ADRs, architecture overview).
2. Read the relevant source files and existing docs. Cross-check every claim against the code — never document behavior that the code does not exhibit.
3. For API docs: extract signatures, types, and examples from the source. Do not invent endpoints or parameters.
4. For ADRs: record the decision, its context, alternatives considered, and consequences. Number sequentially.
5. Produce or update the documentation files in their conventional locations.
6. Produce `specs/<feature-id>/docs.md` with a summary of files created or updated and verification notes (which claims were checked against which source files).
7. Do not delete existing user-authored documentation. Preserve project-specific content and only update the sections that are stale.
