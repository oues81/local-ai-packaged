Run `npx --no-install acos --fix`, then `npx --no-install acos --check`, then `npx --no-install acos --validate`. Review generated, updated, removed, preserved, native, and emulated projections. Never edit a managed projection directly. Treat any missing artifact-class projection as a validation failure. If synchronization fails, fix the canonical source or adapter rather than patching generated output.

The sync command generates the full set of client surfaces declared in `clients.json`. New surfaces from the July 2026 audit:

- **Devin**: `.devin/agents/*/AGENT.md` (custom subagents, experimental), `.agents/agents/*/AGENT.md` (shared standard). `.devin/rules/` is a native CLI surface — Devin CLI reads `.devin/rules/*.md` natively since v3000.x.
- **Codex**: `.codex/rules/*.rules` (Starlark exec-policy rules). `.codex/skills/` is generated with a deprecation banner (`legacy: true`) — `.agents/skills/` is the primary skills location.
- **Kilo**: `.kilo/plugin/acos-hooks.ts` (hooks via plugin system, DD-014). `.kilocode/` paths are generated with a deprecation banner (`legacy: true`).
- **OpenCode**: `.opencode/plugins/acos-hooks.ts` (hooks via plugin system, DD-014).
- **Claude**: `.claude/workflows/*.js` (dynamic workflows, placeholder), `.claude/output-styles/*.md`.
- **Cursor**: `.cursor/permissions.json`, `.cursor/cli.json`.

Projection banners (per `clients.json` schema):
- `legacy: true` projections are still generated but with a deprecation banner at the top of the file.
- `desktopOnly: true` projections are generated with a desktop-only banner indicating the surface is not read by the CLI variant of the client.
- Plugin manifest directories (`.devin-plugin/`, `.codex-plugin/`, `.claude-plugin/`, `.cursor-plugin/`) are declared and fully ACOS-generated — the sync creates the directory and full ACOS-generated manifest.

## Completion checklist

Before declaring sync complete, verify:

- [ ] `acos --fix` was run (show output — generated, updated, removed, preserved counts)
- [ ] `acos --check` was run (show output — no drift)
- [ ] `acos --validate` was run (show output — schemas valid)
- [ ] All declared client surfaces present (check `clients.json` projections list)

**This entrypoint regenerates projections only.** It is NOT a migration. If the project's
`ssotVersion` is behind `CURRENT_SSOT_VERSION`, use `1140-migrate-workflow` instead — syncing
projections on a stale-version project will produce projections matching the old version, not
the current one.

## Reconciliation safety (Bug 9/10 safeguards)

If you are running `acos-migrate --reconcile --apply` (not just `acos --fix`), the non-destructive
rules in `1140-migrate-workflow.md` → "Non-destructive reconcile rules" apply. Key points:

- **Always review the dry-run first**: `acos-migrate --root . --reconcile` (without `--apply`)
  shows `Template-removed entrypoints` (will be DELETED) and `Stale template content` (frontmatter
  will be refreshed, body preserved). Never skip this step.
- **templateRemoved entries are deleted** — the engine uses an explicit `REMOVED_TEMPLATE_IDS`
  registry (not a heuristic). If a listed entry is a legitimate custom, extract its content to
  `.acos/migrations/snapshots/` before applying.
- **staleTemplateContent refresh is frontmatter-only** (Bug 10 fix) — the body is preserved. Do
  not expect full-file hashes to match the template after refresh. Only the `description` field
  in the frontmatter is updated.
- **Custom entrypoints (orphans) are never deleted** by reconcile. They are preserved in both
  source files and `workflows.json`.
