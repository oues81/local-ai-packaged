Upgrade project dependencies in safe batches.

1. Extend `scripts/audit/environment-doctor.mjs` to detect outdated dependencies.
2. Classify upgrades into batches:
   - **Patch**: bug fixes only, lowest risk. Apply first.
   - **Minor**: backward-compatible features. Apply second.
   - **Dev dependencies**: tooling updates. Apply third.
   - **Runtime majors**: breaking changes. Apply last, one at a time.
3. For each batch:
   - Apply the upgrade (`npm update`, `pip install --upgrade`, `cargo update`, `go get -u`).
   - Run the project's test suite.
   - If tests pass, commit atomically with a message like `deps: batch <name> (<count> packages)`.
   - If tests fail, roll back the batch and report the failing package.
4. Produce a summary of upgraded packages, skipped packages (with reasons), and any test failures.
5. Do not upgrade runtime majors without explicit user confirmation — they may require code changes.
6. Respect `minimumReleaseAge` and security policies in the project. Never float to `latest` or unbounded ranges.
