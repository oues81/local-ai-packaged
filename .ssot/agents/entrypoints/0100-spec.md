Convert the supplied objective into a structured, evidence-based specification under `specs/<feature-id>/spec.md`.

0. If `.ssot/constitution.md` does not exist or is empty, prompt the user to run `0060-constitution` first. If it exists, read it before specifying — the constitution constrains all specs.

1. Derive a kebab-case feature ID from the objective. If a spec for the feature already exists, reconcile it rather than creating a duplicate.
2. Read `.ssot/agents/spec-engine.json` and the spec template at `.ssot/agents/specs/spec-template.md`.
3. Inspect existing behavior first. Define scope, non-goals, invariants, acceptance criteria, failure modes, dependencies, compatibility requirements, migration impact, and unresolved decisions.
4. Reconcile contradictions instead of duplicating them. Make every acceptance criterion independently verifiable.
5. Persist the spec and report the feature ID, phase, and any unresolved decisions that need the user. If unresolved decisions remain, suggest running `0120-clarify` to resolve them before planning.
